# Дорожная карта Family Studio

Единый краткий трекер текущей работы. Здесь отмечаются **статус, зависимости, критерий завершения и следующий шаг**; детали персонажа — в brief и [`dad-reference-audit.md`](dad-reference-audit.md), стратегия производства — в [`production-plan.md`](production-plan.md), а решения по локальным reference assets — в [`reference-assets-review.md`](reference-assets-review.md).

Правило статуса: задача считается выполненной только при наличии артефакта/проверки и, когда нужно, явного одобрения пользователя. План или неподтверждённый рендер не равен готовой модели.

## Текущее состояние — 2026-11-01

**Фаза:** профессионально подготовить новый reference-driven process; не использовать ни один прежний mesh. Сначала reference audit и реальный modeling workflow, затем детализированная голова, full figure, production topology, rig и motion proof.

**Сейчас:** пользователь ранее оценил R3 gray blockout на **9/10 как пропорциональную опору**, но теперь явно уточнил, что **blockout тоже не подходит** и его нельзя использовать как основу. Эта последняя коррекция отменяет прежнее согласие использовать blockout как базу. Процедурный R4 v1 ранее получил **1/10 и однозначно отвергнут**. Сейчас **нет одобренной 3D-модели или геометрической базы**.

**Граница одобрения:** оба результата — R3 blockout и R4 v1 — перемещены в `rejected`-архивы только для истории/аудита; ни их геометрию, ни скрипты не использовать для нового персонажа. Активный runtime-harness остановлен и не пересобирает отвергнутые формы. Следующий шаг — не новая primitive/blockout сборка, а reference audit и выбор реального профессионального sculpt/modeling workflow, соответствующего цели. Детали технического harness — в [`blender-wasm-runtime.md`](blender-wasm-runtime.md).

## Непереговорная планка качества

- Переносить текущий 2D/2.5D образ в объём, **не редизайня и не упрощая видимые элементы**: сохранить силуэт, пропорции, лицо, hairline, форму волос/бороды, одежду, цвета, характерные линии и мелкие отличительные детали эталона.
- Цель — визуальное качество не ниже референсного мультсериала; generic/plastic appearance или лишь «похожая» фигура не проходят R4.
- Сверять ракурсы и крупные детали side-by-side с reference plates. Скрытые поверхности, которых нет в источниках, отмечать как неизвестные и согласовывать, не выдумывать без разрешения.
- Технически успешный Blender/Cycles render не равен художественной приёмке. Каждый stage закрывается явным визуальным approval пользователя.

## Ближайшие действия

1. Сохранить новую коррекцию пользователя как текущую: ни R3 blockout, ни R4 procedural mesh не подходят и не являются стартовой геометрией. ✅
2. Подготовить visual reference board, детальный checklist и воспроизводимые silhouette samples из прозрачных master crops; зафиксировать SHA-256 исходников и ограничения измерений. ✅ — см. [`dad-reference-audit.md`](dad-reference-audit.md).
3. Работать с нашей стороны через настоящий Blender WASM Python/Cycles: использовать измеренные силуэты/landmarks для custom continuous surfaces; не возвращаться к generic primitive assembly. Это не ручной sculpt, качество остаётся гипотезой до render/сверки.
4. Создать custom detailed head iteration, достаточную для оценки лица/глаз/бороды/волос; показать PNG side-by-side с front/¾/profile и close-up. Пользователь смотрит на iPhone; `.blend` приложить как исходник, но не требовать desktop для review. Rough blockout не выдавать как accepted base или meaningful likeness result.
5. После likeness approval перенести точный силуэт/объём на тело и одежду, затем материалы, retopology/UV, rig и animation tests. Каждый visual gate — реальные Blender-кадры side-by-side и явный approval.

Оба отвергнутых mesh не дорабатывать и не использовать как старт. Следующий результат должен следовать утверждённым reference masters, а не форме старого blockout.

## Решения, которые считаются зафиксированными

- Основной DCC и целевой proof: Blender; Godot — опционален, не требуется для первого персонажа.
- Первый 3D-герой: папа; затем мама и сын.
- Домашний верх папы: светло-серый crewneck без капюшона — решение пользователя от 2026-11-01. Исходный character JSON не изменяется.
- Legacy 3D prototype — технический справочник и эксперимент, не финальный render/model.
- Не возвращаться к отклонённому 2.5D cutout как к финальному решению.
- Не брать чужую готовую модель вместо семейных героев; внешние ассеты проверять и записывать в asset ledger.

## Изменение плана

Если появляется новый reference, решение пользователя, runtime или технический блокер — добавить это сюда и в соответствующий brief/ledger. Сохранять прошлые решения и причины изменения; закрывать этап только с конкретным выходом и проверкой.
