# Дорожная карта Family Studio

Единый краткий трекер текущей работы. Здесь отмечаются **статус, зависимости, критерий завершения и следующий шаг**; детали модели остаются в персонажных brief, стратегия производства — в [`production-plan.md`](production-plan.md), а решения по локальным reference assets и legacy 3D prototype — в [`reference-assets-review.md`](reference-assets-review.md).

Правило статуса: задача считается выполненной только при наличии артефакта/проверки и, когда нужно, явного одобрения пользователя. План или неподтверждённый рендер не равен готовой модели.

## Текущее состояние — 2026-11-01

**Фаза:** подготовка первого Blender-персонажа — папы.

**Сейчас:** фактический запуск Blender 5.2 WASM в Chromium подтверждён; Blender Python создал Dad gray blockout, три native Cycles рендера и сохранённый/повторно открытый `.blend`.

**Блокер:** технический runtime gate пройден; R3 остаётся открытым до визуального просмотра и решения пользователя. Blockout намеренно грубый, с primitive shells; его нельзя считать одобренной моделью или готовой анимацией. Подробности и ограничения — в [`blender-wasm-runtime.md`](blender-wasm-runtime.md).

## Ближайшие действия

1. **Получить visual review** трёх native Cycles ракурсов папы: силуэт, лицо/борода/волосы, рост и relaxed pose; crewneck без капюшона оставить как подтверждённое решение.
2. На конкретной обратной связи уточнить параметры Blender-сцены и повторно проверить front / ¾ / profile на одинаковом масштабе; blockout остаётся черновиком.
3. Только после явного одобрения сходства закрыть R3 и перейти к чистой топологии, затем body/facial rig и motion proof.

Runtime smoke test завершён, но сам дизайн/модель/анимация не утверждены. Никакого фиктивного подтверждения.

## Решения, которые считаются зафиксированными

- Основной DCC и целевой proof: Blender; Godot — опционален, не требуется для первого персонажа.
- Первый 3D-герой: папа; затем мама и сын.
- Домашний верх папы: светло-серый crewneck без капюшона — решение пользователя от 2026-11-01. Исходный character JSON не изменяется.
- Legacy 3D prototype — технический справочник и эксперимент, не финальный render/model.
- Не возвращаться к отклонённому 2.5D cutout как к финальному решению.
- Не брать чужую готовую модель вместо семейных героев; внешние ассеты проверять и записывать в asset ledger.

## Изменение плана

Если появляется новый reference, решение пользователя, runtime или технический блокер — добавить это сюда и в соответствующий brief/ledger. Сохранять прошлые решения и причины изменения; закрывать этап только с конкретным выходом и проверкой.
