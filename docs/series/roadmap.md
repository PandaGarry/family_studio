# Дорожная карта Family Studio

Единый краткий трекер текущей работы. Здесь отмечаются **статус, зависимости, критерий завершения и следующий шаг**; детали модели остаются в персонажных brief, стратегия производства — в [`production-plan.md`](production-plan.md), а решения по локальным reference assets и legacy 3D prototype — в [`reference-assets-review.md`](reference-assets-review.md).

Правило статуса: задача считается выполненной только при наличии артефакта/проверки и, когда нужно, явного одобрения пользователя. План или неподтверждённый рендер не равен готовой модели.

## Текущее состояние — 2026-11-01

**Фаза:** перезапуск R4 по reference-driven процессу: сначала голова/сходство, затем полная фигура, production topology, rig и motion proof.

**Сейчас:** пользователь оценил R3 gray blockout на **9/10** как рабочую основу. Последующий процедурный R4 v1 получил от пользователя **1/10 и однозначно отвергнут** за большое расхождение с референсом. Это моя ошибка процесса: сборка процедурных форм выдана за hero-model iteration без достаточной сверки сходства.

**Граница одобрения:** R3 — единственная одобренная 3D-основа. R4 v1 перемещён в `assets/models/dad/rejected/` и `assets/renders/dad-procedural-v1-rejected/` только как отклонённый архив; его формы и код не использовать как старт для доработки. Следующий шаг — точное сравнение с master references и новая работа с головой, сначала в 3 видах и только после одобрения — тело/одежда. Детали runtime — в [`blender-wasm-runtime.md`](blender-wasm-runtime.md).

## Непереговорная планка качества

- Переносить текущий 2D/2.5D образ в объём, **не редизайня и не упрощая видимые элементы**: сохранить силуэт, пропорции, лицо, hairline, форму волос/бороды, одежду, цвета, характерные линии и мелкие отличительные детали эталона.
- Цель — визуальное качество не ниже референсного мультсериала; generic/plastic appearance или лишь «похожая» фигура не проходят R4.
- Сверять ракурсы и крупные детали side-by-side с reference plates. Скрытые поверхности, которых нет в источниках, отмечать как неизвестные и согласовывать, не выдумывать без разрешения.
- Технически успешный Blender/Cycles render не равен художественной приёмке. Каждый stage закрывается явным визуальным approval пользователя.

## Ближайшие действия

1. Зафиксировать причины оценки 1/10 и создать reference board: выровнять неизменённые face/front/¾/profile masters, записать landmarks и checklist всех видимых деталей.
2. Построить отдельную форму головы с настоящим контуром черепа/челюсти и читаемыми крупными массами причёски и бороды; сравнить front/¾/profile при одинаковом масштабе.
3. После подтверждения силуэта сделать detail pass головы: веки/радужки/брови/нос/рот, скулы/уши, точный контур бороды и укладку волос. Сверять крупно и в полный ракурс; не переходить к full body без approval сходства.
4. Перенести утверждённый уровень деталей на всё тело и outfit, затем topology/UV/materials, body/facial rig и motion. Каждый gate — реальные Blender-кадры + side-by-side reference comparison и явный approval.

Отклонённый v1 не подправлять косметически: расхождение системное. Новую итерацию начинать с R3 accepted base и полного checklist, а не с failed R4 geometry.

## Решения, которые считаются зафиксированными

- Основной DCC и целевой proof: Blender; Godot — опционален, не требуется для первого персонажа.
- Первый 3D-герой: папа; затем мама и сын.
- Домашний верх папы: светло-серый crewneck без капюшона — решение пользователя от 2026-11-01. Исходный character JSON не изменяется.
- Legacy 3D prototype — технический справочник и эксперимент, не финальный render/model.
- Не возвращаться к отклонённому 2.5D cutout как к финальному решению.
- Не брать чужую готовую модель вместо семейных героев; внешние ассеты проверять и записывать в asset ledger.

## Изменение плана

Если появляется новый reference, решение пользователя, runtime или технический блокер — добавить это сюда и в соответствующий brief/ledger. Сохранять прошлые решения и причины изменения; закрывать этап только с конкретным выходом и проверкой.
